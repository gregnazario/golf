# Contributing to Golf

Golf is a single binary format with six implementations that must stay
byte-compatible. This guide explains how to change things safely.

## The One Rule

**[SPEC.md](SPEC.md) is the source of truth.** Any behavioral change must land
there first, then propagate to every implementation in the same PR. Never fix
a mismatch by changing one implementation's read path alone -- other readers
(or writers) will drift.

Typical safe-change workflow:

1. Update `SPEC.md` (or confirm the spec already says what you need).
2. Change the reference implementation (`rust/`) and run its tests.
3. Propagate the change through `go/`, `python/`, `typescript/`, `swift/`,
   `kotlin/`.
4. Add or extend shared fixtures if the change affects on-disk bytes.
5. Run `bash testdata/run_compat_tests.sh` and require 6/6 green.

If you cannot touch all six implementations, open an issue describing the spec
change instead of landing a partial one.

## Running Everything Locally

```bash
cd rust        && cargo test                     # Rust (reference)
cd go          && go test ./...                  # Go
cd python      && pytest                         # Python (after pip install -e ".[dev]")
cd typescript  && npm install && npm test        # TypeScript
cd swift       && swift test                     # Swift
bash kotlin/scripts/test.sh                      # Kotlin (kotlinc only; no Gradle needed)

bash testdata/run_compat_tests.sh                # cross-language matrix + fixtures
```

CI expectations: every language passes its own suite **and** reads every
fixture generated by the other languages. Swift/Kotlin steps are skipped when
their toolchains are absent (see the guard pattern in the compat script), but
local changes should be verified on a machine that has both.

## Implementation Conventions

Keep the six codebases structurally parallel so audits are diffable:

- Same module split: constants/enums + codecs, core encode/decode structs,
  writer, reader.
- Same error taxonomy and error *messages* where practical (they embed
  expected-vs-got values used by tests).
- Reader behavior is fixed:
  - opening validates footer → index → header (magic/version/CRC32C);
  - block CRCs verify lazily at query time per touched block;
  - queries only decompress blocks overlapping `[start_ts, end_ts]`.
- Writer behavior is fixed: sort ascending (tie order free), partition by
  `block_capacity`, compress independently, prefix LZ4 payloads with
  uncompressed size as LE u32.
- Zero-dependency implementations (Swift, Kotlin) must stay dependency-free;
  their LZ4/CRC32C primitives are ports of each other and of SPEC.md rules.

## Adding Tests

- Every bug fix gets a regression test in the affected implementation(s).
- Cross-language-visible bugs get covered via fixtures when feasible --
  prefer adding a fixture that five languages can check over duplicating logic
  six times.
- Known-answer anchors worth keeping: CRC32C(`"123456789"`) = `0xE3069283`,
  CRC32C(`""`) = `0`. If your codec PR changes compressed bytes, remember only
  *decoded* bytes are contractual.

## Style

Follow the dominant style of each directory (rustfmt / gofmt / black-ish /
prettier-ish / Swift API design guidelines / official Kotlin coding
conventions). Match surrounding comment density; document public APIs, not
obvious statements.

## Commit Messages

Plain imperative summary ("Fix off-by-one in findLastBlock"), details in the
body. Please do not append any AI/tool attribution trailers to commits.
